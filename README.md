# 麦门票根册 · maimen-receipts

> 记录你的每一单，算清每一笔，记住每一个瞬间。

把你的麦当劳订单变成一本可积累、可检索的**票根册**：每单自动核价、拆套餐算营养、补一句当天的记忆，日后一句话就能找回。

**1 单也能出完整票根** —— 不需要攒够一年的数据。

> 本项目为麦当劳程序员节创意开发大赛参赛作品，由参赛者独立开发，非麦当劳官方产品。输出仅供参考，不构成医疗、营养或其他专业建议；餐品信息、价格及供应状态以麦当劳官方渠道的实时结果为准。

---

## 项目介绍

麦当劳 App 里能查到「我这单花了多少」，但查不到「这一个月我一共花了多少、省了多少、吃了多少热量」，更记不住「那天为什么吃这顿」。

票根册补的就是这三件事：

| 层 | 能力 | 产出 |
|---|---|---|
| **记录** | 导入订单，去重入本地账本，跨月可查 | 账本 JSON，历史越积越全 |
| **计算** | 这一单相对原价省了多少；套餐拆子项累加营养 | 每张票根上的数字，全部由代码算出 |
| **记忆** | 给订单补一句话；用一句话找回旧订单 | 补记 / 检索 |

一句话概括分工：**取数交给 MCP，算术交给代码，表达交给 Agent** —— 模型不编任何数字。

---

## 核心功能

**① 精确核价**
用订单自身的金额字段做差（原价合计 − 实付），口径写「这一单相对原价省了 ¥12.70」，不写「帮你省了」（无法证明你会按原价购买）。

**② 营养四档标注**
套餐自动拆成子项逐项累加。每个数字旁标可信度：

| 标记 | 含义 |
|---|---|
| `实测` | 与官方营养表逐项同名匹配 |
| `实测·规格映射` | 官方表有该品项的不同规格，按规格取值 |
| `官方未收录` | 官方表无此项，**不推测、不映射近似品** |
| `估算 ±20%` | 仅当官方值缺字段时用 4-4-9 反推能量 |

钠**永不反推**（由腌料酱料决定，与主料关系弱），缺就缺。

**③ 一句话补记 / 一句话找回**
给订单写一句自己的话（官方交易事实不动），之后按关键词、日期、金额或门店找回。查不到就明确说「没找到」，不替你猜经历。

**④ 票根与票根册**
单张票根 → 单文件 HTML，热敏小票风格，等宽数字。
月度票根册 → 单数 / 支出 / 省下 / 票根流一页看全。

**⑤ 幂等同步**
同一单导入多次仍是一条；接口没返回的旧单不会被删；个人备注在重新同步后保留。

## 目标用户

| 用户 | 痛点 | 票根册解决什么 |
|---|---|---|
| **常吃麦当劳的上班族** | 一个月花多少、省多少说不清，App 翻不到历史 | 每单自动记账，月度小结一页看全 |
| **减脂 / 控卡的人** | 想知道这顿吃了多少，但套餐营养拆不开 | 套餐自动拆子项累加，每个数字标可信度 |
| **爱记录生活的人** | 想记住「那天为什么吃这顿」，但没人记 | 一句话补记 + 一句话找回 |
| **麦当劳重度用户** | 想回顾自己吃过多少单，但没有工具 | 票根册可导出、可积累、可检索 |

## 使用

### 自然语言调用（装好 skill 后直接说）

```
导入我的麦当劳订单，出一张票根
这一单省了多少？
给 9 月 21 号那单补一句：面试结束，奖励自己
找面试那天的票根
出 9 月的票根册
```

Agent 会按 [`SKILL.md`](SKILL.md) 的六步循环执行，所有数字由 [`skill/core/`](skill/core/) 下的代码算出。

### 命令行直接调用（开发者 / 调试）

```bash
# 出单张票根（Demo 账本，免 Token）
python skill/core/export.py --ledger docs/demo/ledger.json --demo -o docs/outputs receipt DEMO-A1
# -> {"ok": true, "file": "docs/outputs/receipt-DEMO-A1.html"}

# 出月度票根册
python skill/core/export.py --ledger docs/demo/ledger.json --demo -o docs/outputs book 2026-10

# 跑验收测试（13 条）
python skill/tests/test_ledger.py
# -> 13/13 passed
```

打开 `receipt-DEMO-A1.html` 会看到：原价 ¥36.60 / 实付 ¥23.90 / **这一单相对原价省了 ¥12.70（省 34.7%）** / 营养已匹配 3/3 项 / 备注「面试结束，奖励自己」。页顶有红色 `演示数据 · DEMO` 横条。

## 配置

**Demo 模式无需任何配置**（使用 `docs/demo/ledger.json` 离线示例账本）。

要导入**真实订单**，需要一个属于你自己的麦当劳 MCP Token：

1. 手机号登录 <https://mcp.mcd.cn> → 控制台激活 → 同意服务协议
2. 放进环境变量（**不要写进任何文件**）：

```bash
export MCD_MCP_TOKEN=<你的 token>
```

3. 拉取订单并入账：

```bash
python scripts/fetch_orders.py
```

MCP 连接配置模板见 [`mcp-config.example.json`](mcp-config.example.json) —— 只有 `${MCD_MCP_TOKEN}` 占位符，不含任何真实凭证。调用清单与业务价值说明见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。

## 数据口径与边界

这一节说明数字是怎么来的，以及哪些事情本 Skill 做不到。**诚实的边界比夸大的功能更有用。**

**核价**
省下 = 订单原价合计 − 实付。原价只取订单自身金额字段或菜单价。不使用下单预估接口的原价字段作为对账基准（该字段与菜单价存在偏差）。实付大于原价的异常单标记为 `anomaly`，不计入统计。

**历史范围**
MCP 的订单查询接口不提供日期区间过滤。因此**账本从你首次使用开始积累**，不承诺补全历史订单。「查某天 / 某段时间」走本地账本，不走接口。

**营养覆盖**
营养数据以官方公布为准。官方表未收录的品项（含部分新上市产品）标 `官方未收录`，票根末尾明示 `已匹配 N/M 项`。**不推测、不用近似品替代。**

**隐私**
账本不保存地址、取餐码、支付号等字段。票根默认不渲染订单号、手机号、地址、取餐码、支付号，只显示订单号末四位。Token 只从环境变量读取，不写入任何文件。

**数据安全**
账本 JSON 解析失败时，先复制为 `ledger.corrupt.<时间戳>.json` 再进入空态，**不静默清空**。
